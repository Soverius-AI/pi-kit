# ADR-0011: Generative UI through CopilotKit's A2UI renderer and pi-kit's MCP Apps host

Status: Accepted
Date: 2026-10-16

## Context

Generative UI needs A2UI surfaces, MCP Apps and an MCP servers panel. CopilotKit's Angular package renders A2UI in the light DOM with a custom `Catalog`, its components read `--a2ui-*` variables that `.pk-a2ui` maps to the design tokens, its A2UI middleware turns a click into a tool-call pair, and `registerRenderActivityMessage` ranks above the built-in renderers.
Its built-in `CopilotA2UIActivityRenderer` hides a surface behind a loader until the data model is an object with a non-empty member, or 8 s elapse; pi-kit's surfaces wrote a bare array at `/specs` and failed that check.
The runtime's `mcpApps` middleware opens its own MCP client per request (HTTP or SSE only, old `_meta` key) while pi already holds the connections.
The stock MCP Apps widget builds its sandbox as a `srcdoc` frame with `allow-same-origin`: the app inherits the renderer's origin, can read its `localStorage` and bearer token, and the desktop CSP (`script-src 'self'`) blocks its inline script.
The `render_a2ui` tool the runtime injects never reaches pi, because `PiAgent` ignores `RunAgentInput.tools`.

## Decision

- **A2UI runtime.** `CopilotRuntime({ a2ui: { agents: ['pi'], injectA2UITool: false } })`. Surfaces come from tool results, not from a model: `details.a2ui_operations` (pi-kit's convention; `mapEvent` emits an `a2ui-surface` activity, `a2ui-surface-<toolCallId>`, before `TOOL_CALL_RESULT`) or a result text that is JSON with `a2ui_operations`, handled by the runtime middleware. `sessionToMessages` rebuilds the same activity from the stored result.
- **Data model.** A surface's data is an object; `updateDataModel` writes `{ path: '/', value: { specs: [...] } }` or any object at a path, never a bare value. `normalizeA2uiOperations` (`libs/pi-adapter`) rewrites a bare array, string, number or boolean at an absolute path into the object at its parent path (`{ path: '/a/b', value: 1 }` becomes `{ path: '/a', value: { b: 1 } }`; `null` stays a delete). It runs in `mapEvent` and `sessionToMessages`, so the live stream and a rebuilt thread agree; a surface that arrives as result text is not rewritten.
- **The run goes through the middleware.** `PiAgentRunner` owns the replay log and calls `agent.run(input)`, so `runWithMiddleware()` chains `agent.middlewares` itself. A click arrives as `forwardedProps.a2uiAction`; the middleware appends the `log_a2ui_event` pair, `a2uiEventPrompt()` prompts pi, and the run replays pi's echo as a user message.
- **A2UI renderer.** `CopilotA2UIActivityRenderer`, registered by `provideCopilotKit({ a2ui: { catalog, includeSchema: false, loadingComponent } })`, renders the `a2ui-surface` activity; nothing else is registered for it, and a click is its `bridgeA2UIAction`. `PkA2uiLoading` is the loading component. pi-kit's own surface wrapper and piece renderers are removed.
- **Catalog.** `apps/renderer/src/app/genui/a2ui-catalog.ts` keeps the basic catalog's id and holds five components: `Card`, `Row` and `Column` (the basic layout plus the `inset` extension), `Badge` and `Table`; everything else is `includeBasicCatalog`. CopilotKit's components are themed by CSS alone in `.pk-a2ui` (`libs/design-system/src/components.css`): the `--a2ui-*` colours, `--a2ui-spacing-m: 0` (the container's `inset` spaces children), button padding, radius and 32px minimum height, the text field's gap and height, `font: inherit` on form controls, heading sizes, `pre-wrap` on `Text`, `accent-color` on checkboxes and sliders. A component is redrawn only when it still looks foreign after theming, one at a time.
- **Frame.** The root `Card` draws `<pk-turn role="pi" [pkGenUiTurn]="messageId()">` around `pk-genui-frame` (title, badge and tone from the card's props through `a2uiCardHeader`, plus "Rendered from A2UI"); a `Card` that is not the root is a plain bordered box. The `Card` finds its message with `inject(CopilotA2UIActivityRenderer)`, an ancestor of every catalog component.
- **Turn carrier.** `pkGenUiTurn` is a directive on the `pk-turn` inside the `Card`, not on CopilotKit's renderer element, which CopilotKit creates through `ngComponentOutlet`. The `pk-turn` carries `data-turn`, `data-after`, `data-cont` and `pk-hot`, so the transcript's hover rule and the graph's `pk-turn[data-after=...]` selector keep working. `.copilot-a2ui-surface-renderer-layout` is `display: block` and the `Card` host is `block w-full`.
- **MCP Apps use pi's connections, not a second client.** `createMcpExtension`'s `createTransport` factory wraps every transport in `McpTap` (`apps/backend/src/mcp/mcp-tap.ts`): it announces `io.modelcontextprotocol/ui` in `initialize`, reads `tools/list` (the only place `_meta.ui.resourceUri` and `_meta.ui.visibility` are visible; it also yields `toolList`) and keeps the `_meta` of every resource read. The factory rebuilds pi's default transport from `@earendil-works/pi-mcp` (`apps/backend/src/pi/mcp-transport.ts`); that coupling is the price of one connection per server.
- **Host contract.** `PiAgent` emits an `mcp-apps` activity (`mcp-app:<toolCallId>`) when a finished call is to an MCP tool that links a `ui://` resource, and answers a run whose `forwardedProps.__proxiedMCPRequest` asks `resources/read` or `tools/call` through `McpService.relay` (restricted to `ui://` URIs and to tools whose `_meta.ui.visibility` includes `app`); a failure is `RUN_FINISHED { result: { error } }`, and the runner takes no lock and writes nothing to the log for such a run. UI-initiated tool calls skip pi's `tool_call` hooks: they run as `definition.execute` on the user's click.
- **Own host, `PkMcpApp`,** registered through `registerRenderActivityMessage`, keeps the stock wire contract but sandboxes differently: the app runs behind `GET /api/mcp-sandbox/proxy.html`, served without the bearer token on the backend's origin (the component refuses to render if that equals the page's origin), in a second frame without `allow-same-origin` under the spec's default CSP plus the resource's `_meta.ui.csp`. Electron's CSP gets `frame-src ${backendUrl}`. The host announces the theme as MCP Apps style variables and draws its frame in a `pk-turn` with `pkGenUiTurn`. The runtime's `mcpApps` option, `provideMCPApps()` and the stock widget are not used.
- **MCP servers.** The MCP servers dialog is now a section of Settings, opened from the sidebar footer's "N MCP servers" and from `/mcp`. Its data comes from the config files (`~/.pi/agent/mcp.json` honouring `PI_CODING_AGENT_DIR`, and `<folder>/.pi/mcp.json` only when the folder is trusted), the status text of pi's own `/mcp` command (`parseMcpStatus`; an unknown line yields no state, not a wrong one) and the tap (tool counts, `toolList`); `McpServer` carries a `signIn` state. Reconnect, sign in and sign out run pi's `/mcp` subcommands; sign-in returns at the authorization URL and the section polls, and `mcpCommand` takes an `input` hook for pi's redirect-URL prompt. Enable / disable writes `enabled` into the file that defines the server (`mcp-config.ts` edits one entry without touching the rest) and then `session.reload()`, refused during a run. REST: `GET /api/mcp?thread=`, `POST /api/mcp/reload`, `POST /api/mcp/servers/:name/{enabled,reconnect,login,logout}?thread=`.
- **Other chat slots.** `pk-prose` stays the `assistantMessageMarkdownRenderer`: CopilotKit's assistant renderer has no streaming caret, no render cache for the transcript window, and hard-codes inline code colours in dark. The user message uses `CopilotChatUserMessage`'s edit button and `CopilotChatUserMessageBranchNavigation` (`(editMessage)`, `(switchToBranch)`), fed by the graph's sibling turns. Before writing a chat component, look for the CopilotKit one first and record here why it cannot be used.
- **Examples.** `examples/a2ui-failing-specs` (a pi extension whose tool returns a surface) and `examples/mcp-app-server` (a stdio MCP server with a form app that announces its UI only to a client that announced MCP Apps).

## Consequences

- A model cannot author A2UI: surfaces come from tool results only; `sendDataModel` and two-way bindings are not sent back to pi, and an action during a run fails with "Thread already running".
- Surfaces that write a bare array keep working through the adapter's normalisation without the 8-second wait; a surface that sets siblings one by one must write them as one object, because an update replaces the parent. CopilotKit's loader shows for a frame or two before a whole surface appears.
- The DOM of a surface is `copilot-a2ui-activity-renderer > pk-a2ui-card > pk-turn > pk-genui-frame`; tests, the e2e suite that looks for "Rendered from A2UI" and the graph rely on it. `genui/` holds the catalog, the loading component, the turn directive and the MCP host.
- The backend carries a copy of pi's transport construction and a parser for its `/mcp` text; both fail soft, and a pi upgrade means re-checking both.
- `PkMcpApp` is the one parallel component pi-kit keeps; it omits `ui/request-display-mode`, `ui/update-model-context`, `ui/resource-teardown` and `_meta.ui.permissions`, and `_meta.ui.visibility` governs only app-to-tool calls, since pi declares every tool to the model.
- Every open thread has its own pi session and so its own server processes; an app's server state is per thread, and a proxied request waits for the agent to be idle. Disabling a server reloads the session; the Settings section says so and refuses during a run.
- The runner has two more kinds of stream that are not conversation turns: a relay for an app and a click turned into a prompt.
