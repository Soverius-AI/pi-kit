# System refactoring plan

Date: 2026-10-24
Branch: `refactor/system-cleanup`

Refactor pi-kit by responsibility, remove duplicated infrastructure, and replace custom mechanisms with maintained packages where they preserve the application's behavior. Each independently working refactoring gets its own commit after its checks pass. Correctness fixes get separate commits from structural changes. There is no target file length, deletion quota, or replacement agent limit.

The first completed change is `1475142`, which removes the four-request background-agent generation semaphore. Completion and validation are tracked below; other items remain planned. Generated HTTP clients and protocol output are regenerated through their owning tools, never split or hand edited.

## Working method and verification

Before each change, read the owning implementation, its callers, existing regressions, and relevant ADRs. Run the smallest meaningful baseline. Describe the behavior that must survive, make one coherent change, then run the affected tests, typecheck/build and lint. Include the appropriate real browser or process check when the behavior depends on layout, transport, concurrency, persistence or shutdown. Inspect the final diff and let the normal commit hook run before committing.

Use the requested `test-audit` skill at `/Users/wolfmanfx/.claude/skills/test-audit/SKILL.md` to judge test usefulness. Each new or changed test must identify its observable contract, a credible regression, why stronger existing coverage does not already catch it, and whether it requires an otherwise unused production seam. A bug regression must demonstrably fail before its fix for the intended reason. Do not rewrite tests just because production code moves, or add tests that assert the new helper layout.

For each proposed test deletion, record its exact name, real failure coverage, production callers, stronger remaining proof, history, unlocked cleanup, risk and validation command before editing. Keep transport, security, durable storage and crash recovery contracts even when they resemble implementation details. Use pi-kit's existing commands for the checks they actually provide.

LLM assertions cover application contracts: a turn streams, an offered tool can run, Stop cancels, a report reaches its thread and usage persists. Do not assert exact generated prose or let the model judge whether the refactor passes. Use scratch agent folders, databases and repositories, as the existing E2E harness does.

Run `pnpm run check` at integration milestones and before the branch is ready for review. Run the relevant E2E suites after each UI or session migration, and the full E2E suite before declaring the overall work complete. Record any baseline failure separately; never delete it to make a refactoring green. Compare performance against the same fixtures, viewport and build before and after. ## TanStack Virtual migration gate

Use [`@tanstack/angular-virtual`](https://tanstack.com/virtual/latest/docs/framework/angular/angular-virtual), which exposes virtualizer state through signals. The adopted version `6.1.8` declares Angular 20+ as its peer requirement and uses virtual-core `3.19.7`; the application uses Angular 22. Its installed source and types are authoritative where the [online API documentation](https://tanstack.com/virtual/latest/docs/api/virtualizer) differs. Pin the compatible version exactly and commit the lockfile with the first adopted consumer.

Start with diffs because they isolate the row measurement problem from chat hydration. The trial must be exercised in the real browser before deleting the current viewport implementation. Keep layout-specific adapters small; share proven scroll/measurement infrastructure only when a second consumer actually needs it. Do not build a generic framework around TanStack.

For **diffs**, preserve the existing outer review scroller and compact transcript scroller. Measure one logical row including its comment/editor additions; split cells contribute the maximum cell height, not the sum. Verify variable-height comments, mode changes, large scroll jumps, files outside the viewport, hidden groups reopening, stable horizontal width from offscreen lines, split-pane alignment and find mounting an offscreen result before revealing its character. Hidden zero-size elements must not erase useful measurements. Run the existing 16,000-line browser fixture in both modes and compact chat rendering.

For the **session tree**, TanStack owns the rendered window, row offsets and scroll-to-index. Domain code still owns lane connections, branch folding, search matching and active-turn selection. Preserve both turn and compaction-band heights and keyboard behavior through filtering and folding.

For the **transcript**, preserve every behavior recorded in [ADR-0032](adr/0032-thread-hydration-and-virtual-transcript.md): complete redacted history, exact replay cursor boundary, variable-height reasoning/tool/generated UI, first-open at the latest message, follow-latest release/resume, Latest button, message-ID plus within-row reading anchors per thread, width invalidation and composer/footer resizing. Scrolling history must not be interrupted by incoming tokens.

Native scrollbar dragging is a specific acceptance case: changing measurements must not move the thumb under the pointer, leave blank gaps or undo the release anchor. TanStack's API documentation does not establish that it satisfies this whole application contract. Verify it in Chromium and Electron. If a narrow rail-freeze/anchor adapter remains necessary, keep only that behavior and document the gap; do not preserve a second range/measurement engine. Do not adopt the chat replacement until this gate passes.

Use `e2e/hydration.e2e.mjs` for its 1,200-turn mixed-height history, beginning/middle/end travel, thumb dragging and streaming. Keep painted coverage and exact reading-position assertions. Audit fixed DOM-count assertions to ensure they guard bounded rendering rather than one overscan constant. Compare mounted DOM, long tasks, scroll coverage and interaction behavior with the baseline on the same fixtures. Preserve privacy: only generated or redacted history enters committed fixtures.

For each limit, identify whether it is a protocol requirement, user policy, presentation choice, resource-control mechanism or an unsupported work restriction. Keep cancellation, avoid silent data loss and preserve full canonical data even when a viewport renders a subset. Do not replace the removed four-agent cap with a different hidden ceiling.

Speech-engine input formats, chunking requirements, cache expiry and log rotation need their documented purposes verified; they are not automatically work restrictions. The crash-loop hold and trust/permission controls have observable recovery/security purposes and remain covered. Operational test deadlines terminate a stuck test and do not become application policy.

Version-library review also found a low-priority upstream limitation: `semver` 7.8.5, like the former comparator,
collapses adjacent numeric prerelease identifiers above JavaScript's safe integer range. Package adoption does
not fix that edge case. An exploratory assertion for those hypothetical identifiers was not retained as a
passing regression; the actual migration gates cover the supported SDK wildcard policy, standard prereleases,
invalid syntax and the application's unknown-version fallback. No custom second SemVer engine was added.
